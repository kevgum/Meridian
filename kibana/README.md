# Kibana Presentation Dashboard

A ready-made Kibana dashboard designed to be **read by anyone** — no programming
or security background needed. Use it when demonstrating Meridian Sentinel to a
non-technical audience.

## What's in it

| Panel | What it tells a viewer |
|-------|------------------------|
| **About this dashboard** | A plain-language explainer at the top of the board |
| **Total Transactions Processed** | How many payments the system checked |
| **Suspected Fraud Detected** | How many payments were flagged as unusual |
| **Security Incidents Raised** | How many flagged cases went to a human analyst |
| **Legitimate vs Suspected Fraud** | A donut showing the safe-vs-flagged split |
| **Transactions by Payment Channel** | Which payment types are most common |
| **Incidents by Urgency Level** | How serious the raised incidents are |
| **Latest Security Incidents** | A simple table of the most recent cases |

Green = safe, red = flagged for review. A date picker at the top right changes
the time period shown.

## How to import it (one time, ~1 minute)

1. Open Kibana at **http://localhost:5601** and sign in (`elastic` / `meridian123`).
2. Go to the menu (top-left ☰) → **Stack Management**.
3. Under *Kibana*, click **Saved Objects**.
4. Click **Import** (top right).
5. Choose the file **`kibana/meridian_overview.ndjson`** from this repo.
6. Leave "Check for existing objects" selected and click **Import**, then **Done**.

## How to open it

1. Menu (☰) → **Dashboard**.
2. Click **Meridian Sentinel — Fraud Detection Overview**.

That's it — the dashboard is ready to present.

## Notes for whoever maintains this

- The dashboard reads from two data views (index patterns): `meridian-transactions-*`
  and `meridian-incidents-*`. These are created automatically by the import, so
  you do **not** need to add index patterns by hand first.
- If the charts are empty, it usually means no data has been ingested yet, or the
  date range is too narrow — widen the date picker (e.g. *Last 90 days*).
- The saved objects are generated by [`generate_saved_objects.py`](generate_saved_objects.py).
  Edit panel wording or fields there and re-run `python kibana/generate_saved_objects.py`
  to rebuild `meridian_overview.ndjson`. Do not hand-edit the `.ndjson` — it is a
  generated file.
- Field names assume Elasticsearch dynamic mapping (text fields get a `.keyword`
  sub-field). If your cluster maps `transaction.type` or `severity` differently,
  update the `FIELD_*` constants at the top of the generator and re-run.
